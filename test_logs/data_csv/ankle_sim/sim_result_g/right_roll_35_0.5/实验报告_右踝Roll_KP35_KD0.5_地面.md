## 3. 物理分析

### 3.1 负载力矩估算

机器人零位站立时，踝关节 Roll 轴承受的重力力矩取决于：
- 体重与重心相对踝关节的侧向力臂
- 零位站立时侧向力臂较小，但不为零

从实验数据推算：
```
实际控制力矩 = KP × (target - actual) + KD × (0 - vel)
           ≈ 35 × 0.015 + 0.5 × 0 = 0.525 Nm (空中理论)

地面实际响应:
  primary_peak_effort = 0.570 Nm (关节输出)
  但实际位移仅 0.75 mrad → 大部分力矩被重力负载"吃掉"
```

### 3.2 失效机理

```
                    空中                              地面
                ┌──────────┐                     ┌──────────┐
 目标 0.015 rad │ τ_ctrl   │ → 位移 14.3 mrad    │ τ_ctrl   │ → 位移 0.75 mrad
                │ = KP×Δθ  │                     │ = KP×Δθ  │
                └──────────┘                     │ - τ_gravity│
                   无外力                         └──────────┘
                                                   τ_gravity >> τ_ctrl
```

**核心问题**：KP=35 产生的控制力矩（~0.5 Nm）无法克服体重施加在踝关节上的重力力矩。重力负载主要通过地面接触力传递，使踝关节成为一个**高刚度负载驱动**场景。

### 3.3 耦合变化

| 指标 | 地面 | 空中 | 变化 |
|---|---|---|---|
| 耦合位移 | −4.689 mrad | 0.005 mrad | **↑ 938x** |
| 耦合峰值速度 | 0.004 rad/s | 0.005 rad/s | 不变 |
| **耦合峰值力矩** | **1.780 Nm** | 0.035 Nm | **↑ 51x** |

地面测试中耦合力矩暴增 51 倍，说明：
- Roll 激励引起了身体侧倾，Pitch 轴需要额外力矩维持平衡
- 这是**地面反力耦合**，而非纯机械结构耦合

## 5. 结论与建议

### 5.1 核心结论

1. **KP=35 在地面完全不可用**：跟踪比仅 5%，无上升时间可言
2. **重力负载是主因**：踝关节需要克服体重带来的力矩才能产生有效位移
3. **基线漂移**：零位站立下重力持续"压迫"关节，每轮基线下降约 0.85 mrad
4. **空中标定结果不可直接迁移到地面**：两个场景的动力学特性完全不同

### 5.2 调参建议

| 方案 | 操作 | 预期效果 | 风险 |
|---|---|---|---|
| **A. 大幅提高 KP** | KP=200~500 | 力矩可能足够克服重力 | 接近电机力矩极限，可能振荡 |
| **B. 增加前馈力矩** | 在 `effort` 字段加入重力补偿 | 将重力负载卸载后再做位置控制 | 需准确估算重力力矩 |
| **C. 使用 stand 姿态** | `startup_pose_mode: stand` | 膝弯曲分担更多负载 | 基线非零，需要适配 |
| **D. 增大阶跃幅值** | `step_amplitude_rad: 0.05~0.1` | 更大力矩驱动 | 可能影响机器人平衡 |

### 5.3 推荐方案

**方案 B（重力补偿前馈）最为根本**：
```
在 StepControl 中的踝关节控制指令添加：
  effort = gravity_torque_estimate
  position = baseline + step
  kp = test_kp (35)
  kd = test_kd (0.5)

这样 KP 只需负责跟踪偏差，而非对抗整个重力负载。
```

如果暂不修改代码，可先尝试 **方案 A（KP=200+）** 作为快速验证。
